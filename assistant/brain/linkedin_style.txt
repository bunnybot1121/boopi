=== EXAMPLE 3 ===
My AI agent had the memory of a goldfish. 🐟

Session after session, it kept generating the same Fibonacci problem. Different wording, same bug. My users were stuck in a loop — and so was I.

This was BugHunt — a coding mentor that watches how you code, spots your recurring mistakes, and generates new challenges targeting your weak spots. Built it at a hackathon with my team, and the bug we had to hunt... was inside the agent itself. 🐛

Here's what went wrong:
I had a rich memory object storing error types, thinking patterns, session history — everything. But when the LLM generated the next problem, it never actually checked what it had already generated.

Profile read ✅
Passed to LLM ✅
LLM ignoring history completely ✅ (unfortunately)

The fix? Before generating, fetch the last 10 problem titles from memory and explicitly tell the model: "Do NOT generate these again."

That's it. One context injection. And suddenly the agent actually remembered.

🔑 The lesson that stuck with me:
Memory being stored ≠ memory being used.
You have to inject it actively into the prompt — not just pass it along and hope the model figures it out.

Biggest takeaway from this hackathon? The visible memory IS the feature. The heatmap, the AI Recommendation banner, the "MEMORY UPDATED" badge — they're not decoration. They're why users trust the system.

Results still pending, but honestly? This was one of my best hackathon experiences. Shoutout to my team — you guys were unreal. 🙌
