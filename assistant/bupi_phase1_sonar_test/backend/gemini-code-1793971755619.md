# BUPI Ultrasonic Vision & 2.5D/3D Environment Reconstruction — Master Specification

## 1. The Core Idea: "Camera-Less Sonar Vision"
Because BUPI operates in dark/smoke-filled zones without RGB cameras and the ESP32 flash is 86% full, we are building a **Digital Image Processing (DIP) & 2.5D/3D Spatial Vision System** powered entirely by **HC-SR04 Ultrasonic Sensors** and **MPU6050 Orientation**, processed on the **Laptop ("Hive Mind")**.

Instead of a camera capturing an RGB pixel array all at once, the ultrasonic sensor sweeps beams across the room, and the Laptop Python backend converts those `(distance, angle)` readings into a multi-channel 2D/3D image tensor (`120x120` pixels, `4 cm` per pixel = `4.8m x 4.8m` room)[cite: 1].

## 2. Two-Stage Hardware Roadmap (How the Sensor Captures the Room)

### Stage 1: Current Bench Test Phase (1x ESP32 + 1x HC-SR04 + Hand-Sweeping)
- **Hardware Currently Connected:** 1x ESP32 (`TRIG = GPIO 5`, `ECHO = GPIO 18` via voltage divider) + 1x HC-SR04 ultrasonic sensor (plus optional MPU6050 on `SDA = 21, SCL = 22`).
- **No Servo Yet (Hand-Swept):** The user rotates and tilts the single HC-SR04 sensor **by hand** to scan the area.
- **How the Laptop Knows the Hand's Angle:**
  1. **Mode 1 (Auto-Pacer Needle):** A visual guide needle sweeps `0° -> 180° -> 0°` on the screen (e.g., 6s period); the user rotates the sensor by hand matching the needle's pace[cite: 1].
  2. **Mode 2 (Step Plotter):** The user aims at a fixed angle and presses Spacebar/Click to plot that exact wedge[cite: 1].
  3. **Mode 3 (Manual Dial):** Dragging an on-screen angle slider[cite: 1].
  4. **Mode 4 (MPU6050 Wrist Tracking):** Live `yaw` and `pitch` angles streamed directly from the MPU6050 if wired[cite: 1].
- **How 1 Sensor Captures 3D Depth (`2-Pass Scan Layer`):**
  - `Pass 1 (Low / Flat)` scans horizontally at table/floor level to record $d_{\text{low}}(\theta)$[cite: 1].
  - `Pass 2 (High / Tilted)` scans tilted slightly upward (or raised by 10 cm) to record $d_{\text{high}}(\theta)$[cite: 1].

### Stage 2: Final Target Robot Mount (2x HC-SR04 + 1x 180° Servo + 1x MPU6050)
- **360° Full X-Y Plane Coverage (Including All Diagonals):** Mounting 2x HC-SR04 sensors **back-to-back** (`0°` Front and `180°` Rear) on a single `180°` servo turret covers the entire `360°` space (all 4 quadrants and diagonals between X and Y axes) in `~0.75 seconds` using `15°` steps (`12 steps x 2 sensors = 24 beams`).
- **2.5D Vertical Stacked Mode:** Mounting 2x HC-SR04 sensors vertically (bottom flat + top raised/angled) captures $d_1$ and $d_2$ simultaneously in a single sweep.
- **Global Angle Fusion Math:** $\theta_{\text{global}} = \theta_{\text{MPU6050\_Yaw}} + \theta_{\text{Servo\_Angle}}$.
- **Continuous "Drive-and-Sweep" Speed Optimization:** While moving forward, the turret sweeps a narrow front cone (`-45° to +45°` in 5 steps = `0.25s` per update) with a `15,000–25,000 us` echo timeout and bidirectional sweeping so the robot never stops to wait for the map to load.

## 3. Mathematical & Image Processing Pipeline (On Laptop Hive Mind)

1. **Polar-to-Cartesian Pixel Projection:**
   Every valid ping `(d_cm, angle_deg)` maps to pixel coordinates `(px, py)` around the Robot Origin `(60, 60)`:
   $$px = 60 + \text{int}\left(\frac{d_{\text{cm}} \cdot \cos(\theta)}{4.0}\right), \quad py = 60 + \text{int}\left(\frac{d_{\text{cm}} \cdot \sin(\theta)}{4.0}\right)$$
2. **Cumulative Input Summing (Log-Odds Bayesian Occupancy Grid + 15° Gaussian Cone):**
   - Uses **Bresenham's Line Algorithm** across a **15° acoustic cone**[cite: 1].
   - Cells between the sensor and `(px, py)` accumulate negative log-odds (`l_free = -0.35` -> **Open Corridor / Floor**).
   - Cells on the `15°` arc at `d_cm` accumulate positive log-odds (`l_hit = +0.85` -> **Obstacle / Wall**).
   - Because inputs are continuously summed over time, random ultrasonic dropouts vanish while real walls become solid.
3. **Differential 2.5D/3D Depth Classification (Endpoint Comparison $\Delta d$):**
   By measuring the distance difference between two endpoints ($\Delta d$), the engine creates 3D depth perception:
   - **Horizontal Endpoint Jump ($\Delta d_{\text{horiz}} = d(\theta_t) - d(\theta_{t-1})$):** If adjacent angles jump by `> 35 cm`, it marks a **Doorway / 3D Depth Portal (Magenta)** — an opening the robot can drive *into*[cite: 1].
   - **Vertical Endpoint Difference ($\Delta d_{\text{vert}} = d_{\text{high}} - d_{\text{low}}$):**
     - $|\Delta d_{\text{vert}}| < 15\text{ cm}$: **Tall Solid Wall (Red, 100% height)**[cite: 1].
     - $d_{\text{high}} - d_{\text{low}} > 35\text{ cm}$: The top beam went far behind the bottom beam! Classifies the near object as a **Low Step / Rubble (Yellow, 25% height)** and carves out the **Open Corridor (Cyan)** behind it[cite: 1].
4. **OpenCV Morphological Dilation (`cv2.dilate`):**
   - Inflates obstacle pixels by the robot's physical radius (`cyan outline`) so A* pathfinding never clips corners[cite: 1].

## 4. Known Flaws & Required Fixes (Hardware & Software Safeguards)
1. **ZERO Dummy/Simulator Data Allowed:** Remove all virtual room simulators (`SIMULATOR (Virtual Room)`) so viewports start 100% blank and only plot real ESP32 ultrasonic telemetry[cite: 1].
2. **Fix Viewport 3 (3D Voxel Extrusion Bug):** Currently, Viewport 3 only extrudes magenta `Doorway Portal` pixels as tall pink sticks and fails to render the red walls and floor[cite: 1]. It must extrude `Tall Wall (Red)` at 100% height, `Low Step (Yellow)` at 25% height, `Open Corridor (Cyan)` as flat floor tiles, and `Doorway Portal (Magenta)` as doorway markers[cite: 1].
3. **Specular Reflection Rejection (>25° Wall Angles):** Smooth walls hit at steep angles bounce sound away; require multi-hit confidence before overwriting established walls.
4. **Acoustic Crosstalk & Timeout:** Cap `pulseIn` at `25000 us` (`400 cm`) and use a 3-sample median filter on the ESP32.
5. **AI Map Reader Integration:** Slice the `120x120` matrix into angular clearance sectors, compute the live **A* shortest path**, and compress into a `20x20` ASCII matrix so the AI navigator outputs live movement decisions (`FORWARD`, `STEER_LEFT`, `STEER_RIGHT`, `STOP`).
